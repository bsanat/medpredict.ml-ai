# Обзор открытых реализаций для MedPredict

Дата проверки: 21 октября 2026 года. Тип исследования: сравнение первичных публикаций, кода и лицензий для выбора экспериментальной реализации.

Для первого исследования нужна регрессия **текущего измеренного систолического давления** по пяти табличным признакам. Классификация гипертензии, восстановление давления по PPG/ECG и прогноз будущего давления решают другие задачи. Их метрики не показывают ожидаемую ошибку MedPredict.

Проверены шесть лицензированных реализаций: две медицинские и четыре общего назначения для табличных данных. Пять качественных публичных реализаций именно NHANES → SBP с теми же пятью входами в этом поиске не подтверждены. Поэтому общие tabular-проекты включены явно, с обоснованием применимости. Готовые веса и чужие тренировочные выборки не использовались.

## Что проверено глубже

В [дереве sysdevelopment/phd](https://github.com/sysdevelopment/phd/tree/353c6758ce483b27cc6114bf8b1b90c5c7006eb2/source_code) находятся `_SAS DATASET_CREATE.ipynb` и `_NHANES_Conversion From Continuous to Categorical.ipynb`. Исходные ячейки подтверждают join по `SEQN`, удаление пропусков, среднее `BPXSY1/2/3`, удаление этих измерений из predictors и категоризацию возраста/ИМТ. В дереве не найдены отдельный скрипт обучения ANN, зафиксированная среда и тесты. Есть локальные Windows-пути, а merge не проверяет кардинальность. Поэтому публичная доступность материалов даёт частичную проверяемость подготовки, но не доказывает воспроизводимость ANN и её опубликованных метрик.

В [rtdl `lib/data.py`](https://github.com/yandex-research/rtdl-revisiting-models/blob/e3ed46cac38568785289d8fa16b8cfa585bde27e/lib/data.py) проверено обучение normalizer на `X['train']` с последующим преобразованием остальных частей. В [PyTorch Tabular DataModule](https://github.com/pytorch-tabular/pytorch_tabular/blob/826a4c002b43a34a295a6ac58a170e96f396dcbe/src/pytorch_tabular/tabular_datamodule.py) проверено разделение `fit_transform` и `transform`. Это применимые инженерные примеры; их наличие не освобождает наш pipeline от собственных проверок утечки.

В [TabM paper README](https://github.com/yandex-research/tabm/blob/28e47ae301c92ec37787dde1ce923a0793f405b4/paper/README.md) проверены отдельные команды настройки и оценки по нескольким seed, сохранённые конфигурации и отчёты. Исходное значение `metrics.test.score` нельзя автоматически считать R² или MAE: смысл зависит от задачи и реализации метрики.

## Дополнительные кандидаты, которые не стали основой

- [LeoGrin/tabular-benchmark](https://github.com/LeoGrin/tabular-benchmark), сопровождающий [Grinsztajn et al., 2022](https://arxiv.org/abs/2207.08815), полезен как научное обоснование сравнения с деревьями: работа охватывает 45 разнородных табличных наборов и учитывает настройку гиперпараметров. README предоставляет команды, OpenML suites и результаты. Но в корне проверенного дерева `9d54cf53d9fd` нет общей лицензии, [API](https://api.github.com/repos/LeoGrin/tabular-benchmark) возвращает `license=null`. Лицензии внутри отдельных заимствованных подпапок не лицензируют весь репозиторий. Поэтому читаем методику и цитируем статью, общий код не копируем. `pushed_at=2024-08-18` не подтверждает активную текущую поддержку.
- На Hugging Face найден [MedIntel-clinical-risk-models](https://huggingface.co/Sushantak17/MedIntel-clinical-risk-models). Карточка заявляет MIT, NHANES 2017–2018, три XGBoost-классификатора болезней и 35 входов, включая HbA1c/eGFR/гемоглобин и синтетические тренды. Карточка также описывает построение labels по клиническим критериям. **Вывод аудита:** нужно исключить риск восстановления определения label из тех же анализов и проверить независимость синтетически расширенных участников; почти идеальный AUROC сам по себе этого не доказывает. Это другая задача, её веса не подходят нашему входу/выходу. Наличие утечки не утверждается как доказанный факт: исходный training pipeline не был полностью проверен и воспроизведён.
- [PulseDB](https://github.com/pulselabteam/PulseDB) и [статья авторов](https://pmc.ncbi.nlm.nih.gov/articles/PMC9944565/) дают полезный контрольный пример: calibration-based тест и тест на новых участниках — разные протоколы. Это ECG/PPG/ABP сегменты из MIMIC/VitalDB, а не пять клинических полей. Код/данные имеют неодинаковые условия: в README отдельно указаны ODbL/DbCL и CC BY-NC-SA для разных файлов. Сигнальные веса и чужие ошибки измерения не заимствуем.

## Решение для собственной модели

Рекомендация, а не утверждение о достигнутом качестве:

1. Самостоятельно обучить маленькую PyTorch MLP на официальном NHANES с закреплёнными входами, единицами и порядком. Стандартная архитектура `5 → 32 → 16 → 1` не нуждается в копировании медицинского репозитория. Начальные веса обучаются на нашем train, без чужого pretrained checkpoint.
2. Сравнить mean baseline, Ridge, дерево/бустинг и MLP при одном participant-level split. Бюджет настройки зафиксировать; выбирать по validation, закрытый test использовать после фиксации выбора.
3. Из открытых работ взять проверяемые приёмы: train-only preprocessing; отдельные конфигурации и seed; отчёт по каждому запуску; понятные команды; сохранение схемы/преобразований вместе с весами. В коде MedPredict реализовать минимально необходимое на PyTorch/scikit-learn.
4. Не делать возрастные/ИМТ категории только потому, что они были в классификационной статье. Не добавлять SBP, DBP, hypertension label, производные target или идентификатор участника в predictors. Лекарства использовать как контекст анализа и возможного следующего эксперимента, без изменения пятипризнакового контракта по итогам просмотра test.
5. Если нейросеть слабее Ridge/бустинга, честно оставить её исследовательской и выбрать лучшую проверенную модель для приложения. Качество в NHANES не равно качеству в Казахстане и не делает результат диагнозом или заменой измерения.

Оригинальный вклад команды — определение задачи и входного контракта, собственный проверяемый pipeline данных, обучение весов, честное сравнение и анализ ошибок, экспорт и проверка Python/ONNX/Java, интеграция с приложением. Новизна архитектуры стандартной MLP не заявляется.

## Границы проверки

Проверены первичные README, выбранные исходные файлы, тексты лицензий, деревья и метаданные GitHub API, научные публикации и карточка Hugging Face. Полный перебор всех GitHub/HF проектов не проводился; отсутствие найденной подходящей модели не доказывает её отсутствие вообще. Внешние проекты не устанавливались, их обучение, тесты, опубликованные значения и ONNX-экспорт не воспроизводились. Сырые XPT/CSV/MAT и модельные веса для этого обзора не скачивались; медицинские строки не включались в документацию. Фактические результаты MedPredict должны находиться в отдельном отчёте эксперимента.
